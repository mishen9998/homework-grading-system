# 数据库迁移指南（供另一台电脑的 Codex 或编程助手执行）

## 先读：目标与禁止事项

将当前 Flask/Vue 项目的 MySQL 业务库及附件迁到另一台电脑；不包含公网部署、千人并发承诺、多机构商业版本验收。默认单助手顺序操作。

- 源库是关键数据，**禁止 DROP、清表、重置密码、覆盖原附件**。
- 使用同一份代码、数据库迁移文件和配套备份。不要混入 `-campus` / `-saas` 或旧流水线未验收分支。
- 不将真实连接密码写入本文或命令行参数；不要打印 `.env`、备份 SQL、账号记录、密码哈希或 API Key。
- 备份中的 `users.password` 是应用登录校验数据，必须原样迁移。数据库服务用户及授权不在业务备份中，需在目标 MySQL 另行配置。迁移后应用用户的密码不需要重设。
- 备份仅接受自己导出的可信文件；SHA-256 用于发现损坏，不是数字签名，也不能让未知来源 SQL 变安全。
- 所有命令以下均在项目根目录执行。遇到非零退出码停下检查，不用 `stamp head`、忽略错误或删库重试掩盖问题。

## 1. 环境与要带走的资料

目标机准备 MySQL 8.0（优先与源机相同小版本）、Python、Node.js/npm；将 MySQL 的 `bin` 加入 PATH，确认 `mysql` / `mysqldump` 可用。当前演练源端为 MySQL 8.0.45。

```powershell
python -m pip install -r backend/requirements.txt
python -m pip install -r backend/requirements-dev.txt
npm.cmd --prefix frontend ci
```

Linux/macOS 使用 `npm` 代替 `npm.cmd`。可选本地 BGE 语义检索另安装 `backend/requirements-embeddings.txt`，复制原有 `backend/models/bge-small-zh-v1.5` 模型目录；默认不联网下载模型。

必须交接：项目源代码（包含未提交但需要交付的本轮修改）、`backend/migrations/`、本目录工具、完整的一个 `backups/<时间-标识>/` 目录。不要只复制 `users` 表，否则课程、提交、聊天等关联会断开。

运行配置单独安全交接/重建：`backend/.env`、必要的本地 AI 模型及服务配置。建议目标机重新生成应用签名密钥（会使旧登录凭证失效），不要带走公网 API Key，除非用户明确需要。Redis 临时任务/缓存不作为业务备份：停机前完成或处理排队任务。Qdrant 是候选索引，可由 MySQL 中的资料和向量重建；首次恢复使用全新专用集合，不混用旧测试集合。

## 2. 源机检查与停写备份

```powershell
python -X utf8 tools/database/manage.py check
```

记录数据库名、版本、表行数、迁移版本及外键孤立数；不展示账号明细。工具默认只读取 `backend/.env` 的 `DATABASE_URL`，不会误用终端中的其他项目连接串。

停止**本项目** Web/worker/定时写入，通知其他使用者退出；保留 MySQL 服务运行。确认没有其他客户端正在改动后：

```powershell
python -X utf8 tools/database/manage.py backup --writes-stopped
```

`--writes-stopped` 是操作者确认，不会替你停止程序。工具导出 InnoDB 单事务 SQL；生成前后逐表内容摘要、行数及附件校验；检测变化则不生成完成清单。它不能替代停写，也不提供多系统不停机一致性快照。

成功目录有：`database.sql`（结构、密码哈希与业务记录）、`attachments.zip`、`manifest.json`（版本/表行数/内容摘要/文件 SHA-256）。当前支持默认附件路径 `backend/app/tupian/`、`backend/app/uploads/`、`tupian/`；知识库二进制附件已包含在 MySQL 内。自定义附件目录必须先单独核对，不可遗漏。

使用 `--result-file` 导出避免 PowerShell 重定向编码问题；以 [MySQL 官方 mysqldump 文档](https://dev.mysql.com/doc/refman/8.0/en/mysqldump.html) 为依据。工具遇到视图、触发器、存储过程、事件、非 InnoDB 表会拒绝通用备份，须另行核对依赖，不可直接忽略。

## 3. 目标机连接配置

复制 `connection.env.example` 为本目录的 `connection.local.env`，在本地编辑数据库服务地址、账号和密码。密码中的 `@ : / # %` 等需要 URL 编码。使用仅有必要权限的数据库账号；迁移操作需建库/建表/导入权限，日常 Web 运行不建议使用 root。

```powershell
python -X utf8 tools/database/manage.py --env-file tools/database/connection.local.env restore --backup "tools/database/backups/实际备份目录" --target homework_migrated --confirm-target homework_migrated
```

`homework_migrated` 必须不存在；工具会新建它，拒绝导入到配置中的源库、已有库或系统库。首次连接的配置库名可写 `homework`，不要求目标机已存在该库。导入失败会保留现场，不自动删库；查清原因后换一个明确的新库名重试。

工具核对所有表结构、行数和内容摘要，并把附件解压到 `tools/database/local/restored-homework_migrated/`，**不会覆盖运行目录或自动切换应用**。

```powershell
python -X utf8 tools/database/manage.py --env-file tools/database/connection.local.env verify --backup "tools/database/backups/实际备份目录" --target homework_migrated
```

必须 `matching=true`。外键孤立数应为零；若源库已存在异常，记录并人工确认，不自动删除。

## 4. 数据库升级或全新安装

恢复后先对新副本升级，不直接在源库操作：

```powershell
python -X utf8 tools/database/upgrade.py --env-file tools/database/connection.local.env --database homework_migrated --apply
```

当前迁移头为 `d41c8ef013a2`，补齐知识分块表及 50,000 中文字符的正文容量。历史库可能没有 `alembic_version`，工具会执行历史迁移；不会伪装已升级。当前支持本项目完整旧库，不保证任意手工残缺库自动修复。MySQL DDL 非原子回滚，失败时保留副本并停止切换。

完全没有业务数据、确实要新建空系统时，走不同分支：

```powershell
python -X utf8 tools/database/upgrade.py --env-file tools/database/connection.local.env --database homework_new --create-empty --apply
```

空库不含任何默认管理员/师生账号；不要把“初始化成功”当成“已有账号迁移成功”。旧初始迁移只修改已有核心表，所以工具先在真正空库按模型建表，再逐条执行迁移。不可对含业务数据的库执行空库初始化。

## 5. 切换配置、附件和索引

停止目标机本项目应用。把 `backend/.env` 的 `DATABASE_URL` 改为新库；设置 `AUTO_CREATE_TABLES=false`，以后显式升级，避免普通启动被误认为完成历史迁移。重新配置随机 `SECRET_KEY` / `JWT_SECRET_KEY`，前端地址白名单与端口一致。

将暂存目录中的附件按同名相对路径复制到目标项目：例如 `.../restored-homework_migrated/backend/app/tupian/` 对应目标 `backend/app/tupian/`；聊天附件对应 `backend/app/uploads/`。目标已有同名文件时先比对哈希，不允许不加检查地覆盖。源附件及备份保留。

可选索引配置：`LOCAL_EMBEDDING_MODEL` 指向目标机模型绝对路径；配置本地 `QDRANT_URL` / `QDRANT_API_KEY`，为本项目使用独立 `QDRANT_COLLECTION` / `QDRANT_CHUNK_COLLECTION`，避免不同数据库相同记录 ID 相互覆盖。模型标识基于文件内容而非绝对路径，同一份模型搬家后保持兼容；模型内容或分块策略变更后须重建。

```powershell
python -X utf8 backend/rebuild_knowledge_embeddings.py
```

这是本地向量重建/同步，不调用 DeepSeek。管理员网页全量重建仍是同步操作，资料多时使用上述命令维护，不在高峰期点击。Qdrant 不可用时走有上限的数据库候选检索，速度/召回范围可能下降，不能当作全量语义检索。不要手工删除 MySQL 里的知识原文。

## 6. 验证与回滚

```powershell
Push-Location backend
python -X utf8 -m pytest tests -q
Pop-Location
npm.cmd --prefix frontend test
npm.cmd --prefix frontend run build
python -X utf8 start_all.py
```

Linux/macOS 进入 `backend` 运行同样的 pytest 命令后返回项目根。不要让测试连向真实库；默认测试配置使用内存库，不加载本机 Redis/Qdrant。

确认前端登录页、`/api/status/health`、`/api/status/ready` 正常；用用户自己提供的有效账号分别检查教师/学生/管理员登录、课程列表、历史作业与成绩、头像/课程/聊天附件及知识检索；只在合成测试库做新增作业和提交演练。迁移不能以 HTTP 200 或首页能打开代替完整业务核对。

如需回滚：停止目标机应用，把连接配置改回保留的原库/已验证备份副本，并恢复匹配版本的代码和附件。不要尝试把 MEDIUMTEXT 降为 TEXT，这可能丢失长中文内容。回滚后重新登录；新写入数据的合并由用户确认，不能静默丢弃。

最终交接必须写清：源/目标库名、代码版本与未提交改动、备份目录及校验、迁移版本、附件数量/哈希、测试结果、服务地址、仍未验证的功能。不要宣称已商业上线或通过高并发验收。
