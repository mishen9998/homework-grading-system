## 2026-09-19 迁移版本对齐 + 桌面助手就绪探针修复

- 原始操作日志：`tools/database/local/upgrade-20260919-023225.log`
- 操作前备份：`tools/database/backups/20260918T183234Z-a29aa3/`（16 张表 / 359 账号 / 5 个附件，含清单校验）

### 1. 发现的问题

1. **迁移版本落后**：数据库停在 `d41c8ef013a2`（knowledge_embeddings），而代码迁移头为 `d10a00100001`（organization_foundation）。桌面助手启动时的 `database_ready` 门禁因此拒绝启动（该检查只读、无副作用，属预期防护）。
2. **桌面助手就绪探针被组织中间件拦截（隐藏缺陷）**：升级数据库后端到端验证仍失败，排查发现两处适配缺口——
   - `desktop_assistant/service.py` 注册的状态探针端点函数名为 `health` / `ready`，而 `organization_context.py` 的免认证白名单按 `run.py` 的约定放行 `health_check` / `readiness_check` 两个端点名 → 探针请求被误判为未认证（401），助手永远等不到就绪。
   - 助手的 SPA 兜底路由使未知 `/api/*` 路径有了端点名，全局 JWT 校验对其返回 401；正确行为是 404（401 会误导前端登出跳转，`run.py` 无兜底路由时即 404）。

### 2. 执行的操作（按序，全程停写）

| 步骤 | 命令 | 结果 |
| --- | --- | --- |
| 只读预检 | `python -X utf8 tools/database/manage.py check` | 无孤儿外键、无非 InnoDB 表 |
| 停写全量备份 | `python -X utf8 tools/database/manage.py backup --writes-stopped` | 生成 `backups/20260918T183234Z-a29aa3`，清单校验通过 |
| 结构升级 | `python -X utf8 tools/database/upgrade.py --database homework --apply` | `d41c8ef013a2 → d10a00100001`，无缺失字段 |
| 升级后校验 | `manage.py check` + `database_ready(full=True)` | 通过；业务数据不变（users 359 / submissions 1020），新增 `organizations`(2)、`organization_classes`(25) |
| 代码适配 | `desktop_assistant/service.py` 端点改名为 `health_check` / `readiness_check`；`organization_context.py` 白名单放行 SPA 兜底端点 `frontend` | 详见下节 |
| 端到端验证 | `python -m desktop_assistant.verify_local --run-local` | 两轮启停就绪、停止重启、管道关闭退出全部通过 |

### 3. 代码适配说明（本次随日志一并提交）

- `desktop_assistant/service.py`：状态探针端点名改为与 `run.py` 一致的 `health_check` / `readiness_check`，命中组织上下文中间件既有的免认证白名单；路由 URL 不变。
- `backend/app/services/organization_context.py`：`authenticate_request` 白名单补充 SPA 兜底端点 `frontend`——未知 `/api/*` 路径由助手兜底路由的既有守卫返回 404，与 `run.py` 行为一致；业务 API 认证不受影响（全部为蓝图端点）。

### 4. 验证证据（2026-09-19）

- `verify_local`：`cycle 1/2 ready`、`duplicate_start_same_process`、`spa_assets_api_and_private_paths`、`stop_and_restart`、`parent_pipe_eof_shutdown` 全部 passed。
- 回归测试：后端 `115 passed / 26 skipped / 15 subtests`（与升级前基线一致）；前端 `node --test 5 passed`；`vite build` 成功。
- 升级后数据摘要：`alembic_version=d10a00100001`，`organizations=2`（default/platform 种子行），`organization_classes=25`，原业务表行数与内容摘要不变，外键孤儿为零。
